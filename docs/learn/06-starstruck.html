Lesson 6: Starstruck

Badge: a repository receives stars.

TierStars on one repo
Base16
Bronze128
Silver512
Gold4096

This is the one badge you cannot earn alone, which makes it the most meaningful. Stars are bookmarks from strangers saying "this is useful" or "this is cool."

The real skill: shipping a project people want

1. Build something worth starring

  • Solve a problem you have. Others probably have it too.
  • Small and polished beats big and half-finished.
  • Games, dev tools, templates, plugins and "awesome lists" all do well.

2. Make the README sell it in 10 seconds

  • One-sentence description at the top
  • A screenshot or GIF of it working
  • A live demo link (GitHub Pages is free: Settings → Pages)
  • Install/usage in three steps or fewer
  • License (Add file → Create new file → LICENSE shows a license picker)

3. Make it findable

  • Add topics (the next to About on the repo page), e.g. game, threejs, wordpress-plugin
  • Write a clear About description and add the website link
  • Add a social preview image (Settings → General → Social preview)

4. Share it where it's relevant

  • Communities related to your topic (subreddits, Discords, forums), following their self-promotion rules
  • Show HN, dev.to or Hashnode write-ups about how you built it
  • Your own site, newsletter or social accounts
  • Link from wherever else the project lives (itch.io, WordPress.org, npm, etc.)

5. Keep it alive

Respond to issues, merge good PRs, and publish releases. Active projects keep collecting stars.

Never

  • Buy stars, or use "star exchange" groups
  • Star your own repo from alt accounts
  • Make "please star" requests a condition of anything

Fake stars are a well-documented problem that GitHub actively hunts down, and its policies ban rank abuse. Accounts and repos involved can be removed. See FAIR-PLAY.md.

What you learned

  • README and documentation craft
  • GitHub Pages, topics and social previews
  • Honest promotion and community building

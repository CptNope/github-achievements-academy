The real skill: helping people well

Discussions are forums inside repositories. In Q&A categories, the person who asked (or a maintainer) can mark one reply as the answer. Answering well is a career skill. It's how maintainers, support engineers and developer advocates build their reputations.

How to write an answer people accept

  1. Reproduce first. Make sure you understand the problem before replying.
  2. Lead with the fix, then explain why it works.
  3. Show code in fenced blocks with the language noted.
  4. Link the docs you used, so they can learn more.
  5. Follow up. "Did that work for you?" goes a long way.
  6. If you're not sure, say so. A wrong confident answer is worse than none.

Where to practice

  • This repo's Discussions → Q&A. Learners ask questions about the lessons. If you've done a lesson, you can help someone stuck on it.
  • github.com/orgs/community/discussions, GitHub's own community forum.
  • The Discussions tab of tools you already use (frameworks, libraries, CMS plugins).

Honesty check - Never ask questions from one account and answer them from another.

  • Don't ask friends to mark your answers. Let the answer earn it.
  • Don't copy someone else's answer, or paste unverified AI output, as your own.

What you learned

  • Writing clear technical answers
  • Discussions categories and Q&A
  • Building a public reputation for helpfulness
